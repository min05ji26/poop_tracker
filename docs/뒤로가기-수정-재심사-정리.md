# 뒤로가기 수정 & 재심사 정리 (2026-09-09)

## 1. 반려 사유

> **최초 화면에서 내비게이션 바의 뒤로가기 클릭 시 미니앱이 종료되지 않아요.**
> 최초 화면에서 내비게이션 바 뒤로가기 클릭 시 미니앱이 종료되도록 구현해 주세요.

토스 미니앱은 루트(최초) 화면에서 상단 내비게이션 바의 ‹ 뒤로가기(안드로이드는 기기 뒤로가기 포함)를 누르면
앱이 닫히고 토스로 돌아가야 한다. 이 앱은 그 이벤트를 처리하는 코드가 아예 없어서, 심사자가 눌렀을 때
아무 반응이 없었다 → "미니앱이 종료되지 않는다"로 반려.

## 2. 원인 분석 (생각 과정)

- **"종료 버튼을 만들어야 하나?"** → 아니다. 내비게이션 바는 토스 앱이 웹뷰 위에 직접 그리는 것이고,
  그 ‹ 를 누르면 토스가 `backEvent`를 웹뷰로 보낸다. 웹 코드가 할 일은 **그 이벤트를 구독해서 처리**하는 것.
- 루트 화면에서 back → 앱 종료(`Screen.close()`), 하위 화면에서 back → 앱 안에서 이전 화면으로.
- 관련 API: `@apps-in-toss/web-framework` 의 `graniteEvent.addEventListener('backEvent', { onEvent })`
  + `Screen.close()`. (토스 개발자 커뮤니티에서 안내하는 "진입 페이지에서 backEvent 구독 + close" 패턴과 동일)

## 3. 1차 구현과 그 과정에서 발견한 문제

1차로 `backEvent` 처리 + "기록 중 뒤로가기 시 확인" 을 `window.confirm()` 으로 넣었다.
→ 테스트에서 **기록 화면에서 뒤로가기가 안 먹고, 확인창도 안 뜨고, 원래 있던 미래 날짜 `alert()` 경고도 사라진** 현상.

**공통 원인:** 토스 웹뷰에서는 브라우저 기본 다이얼로그(`window.confirm` / `window.alert` / `window.prompt`)가
동작하지 않는다. 토스 개발자 문서도 "브라우저 기본 다이얼로그 대신 자체 모달을 쓰라"고 안내한다.
- `window.confirm()` → `undefined`(falsy) 반환 → `if (!confirm(...)) return` 코드가 항상 early return → 버튼 먹통
- `window.alert()` → 조용히 무시 → 미래 날짜 경고가 안 뜸

## 4. 최종 해결 + 곁들여 정리한 것

| 구분 | 내용 |
|---|---|
| **핵심(반려 대응)** | `src/tossBridge.ts` 신규 — `onBackButton()`(backEvent 구독), `closeApp()`(`Screen.close`). `src/App.tsx` 에서 화면별 분기: 온보딩/홈/로딩 → **앱 종료**, 달력 → 홈, 기록 → 달력 |
| **곁들여 추가** | `src/components/AppDialog.tsx` 신규 — 앱 내부 확인/알림 모달(앱 색감, 확인/취소, `danger` 옵션) |
| **곁들여 교체** | 기록 나가기 확인 · 기록 삭제 확인(`Record.tsx`), 미래 날짜 경고(`Calendar.tsx`) → `window.confirm`/`alert` 전부 `AppDialog` 로 교체 |

동작:
- 홈에서 뒤로가기 → 앱 종료
- 달력에서 뒤로가기 → 홈
- 기록에서 뒤로가기 → 입력한 내용이 있으면 "입력한 내용이 저장되지 않아요. 그만둘까요?" 모달 → "그만두기"면 달력, "계속 쓰기"면 유지 / 입력이 없으면 바로 달력
- 기록 삭제 → "이 기록을 삭제할까요?" 모달(빨강 확인)
- 미래 날짜 + 버튼 → "아직 오지 않은 날이에요. 오늘까지만 기록할 수 있어요." 모달

## 5. 배운 것 / 얻은 것

1. **토스 내비게이션 바는 네이티브가 그린다.** 웹에서 바를 만드는 게 아니라 `backEvent`를 처리한다.
   루트 화면 종료는 `graniteEvent` 구독 + `Screen.close()`.
2. **토스 웹뷰에서 `window.confirm`/`alert`/`prompt` 쓰지 말 것.** 안 뜨거나 falsy 반환으로 로직이 깨진다.
   확인/알림은 전부 앱 내부 컴포넌트(`AppDialog`)로.
3. **로컬에서도 테스트 가능하다.** `@apps-in-toss/devtools` mock 이 `backEvent`를 시뮬레이션한다.
   콘솔에서 `window.dispatchEvent(new CustomEvent('__ait:backEvent'))` → mock 의 `closeView()` 가
   `[@apps-in-toss/devtools] closeView called` 로그를 남긴다. 우하단 **AIT** 패널로도 가능.
4. `history.replaceState()` / 라우터 히스토리 조작은 토스 네이티브 종료 얼럿을 깨뜨린다.
   (이 앱은 라우터 없이 React state 전환이라 무관하지만, 나중에 라우터 도입 시 주의.)
